# Stage 2: interactive, game-like and rich experiences — research archive

Stage 2 asked what the skill must know to judge and build rich interactive work (the Cake Studio lesson: an illustrated, game-like builder beat a technically good 3D one), and to verify ordinary work more thoroughly (widths, content, motion, RTL, polish). It ran on 2026-09-28/29 after the product-ui-mode and greenfield-discovery merge.

**Method.**
1. **Baseline** (`00-baseline.md`, `.json`): three read-only agents mapped 48 topics from the brief against the merged skill, quoting its most specific line on each. Result: 10 known well, 28 shallow, 4 skipped (game-UI canon, sprites, sound and haptics, libraries for hard UI), 4 principles without implementation (motion verification, undo/redo, width sweeps, device tiers), 1 generic, 1 untested.
2. **Twelve streams**, each one lab agent that researched (GitHub sources, npm, search snippets) and built experiments with one reproducible runner, then a skeptic that re-ran the key measurements and checked licence and support claims against primary sources, then an amendment that corrected the report. Evidence tags: [V] primary source, [L] this lab, [S] search snippet, [K] prior knowledge.
3. **Integration plan** (`01-integration-plan.md`): where each finding goes in the skill (core / specialist / archive), which proposals overlap and where each lands once, the eleven decisions that change or reverse something the skill says, the scripts to fix, extend or promote, and what was rejected.

**Status when stage 2 was concluded** (at the user's request, before the document integration began):
- The reports, reviews, experiments and the plan are complete and archived here.
- Script work already in flight was allowed to finish and landed in `skills/website-redesign/scripts/` (see the repository `REPORT.md`).
- **The skill's documents do not yet carry the stage-2 findings.** The plan lists the 31 destination files, the four new references (`interactive.md`, `configurators.md`, `generative-visuals.md`, `resources/hard-ui.md`) and the word budget for each; it is the brief for the next session.
- Blind round 5 (Stem & Wren, Hallam & Price; `experiments/H-blind-eval/round5-prompts.md`) is prepared and has not run.

## Streams

| Stream | Question | What it found that changes a decision | Built |
| --- | --- | --- | --- |
| S1 `rendering-lab` | What should render an interactive scene? | With the main thread 4× slower, DOM and SVG held ~200 continuously animated objects, Canvas 2D ~400, a Worker ~700. An engine's first frame is 3–13× the DOM's. Phaser is 361 KB gzip and cannot be tree-shaken; R3F's `<Canvas>` pulls all of three.js (309 KB; 189 KB with `createRoot` + `extend`). One mesh per object costs 18–19 ms of JS per frame at 2,000 objects; instancing cuts it 8–14×. No full engine exposes DOM accessibility on the web. | The same scene in DOM, SVG, Canvas 2D, a Worker, PixiJS, Phaser, three.js and R3F; a decision table |
| S2 `motion-lab` | Which animation tool for which job; why approved motion disappears | View Transitions swallow input for their whole duration. Motion's transform-string path starts from `scale(0)` without a from-keyframe and jumps when interrupted. CSS kept moving through a 400 ms main-thread block; the libraries froze. Scroll features in GSAP, anime.js and React Spring keep `requestAnimationFrame` running at rest (54–73/s). The seven interactions cost 2 KB in CSS/WAAPI, 28–57 KB in libraries. | `scripts/motion.mjs` (a motion spec checker with filmstrips; held-out precision 0.77) |
| S3 `assets-and-3d-pipeline` | Where assets can come from, and how to prepare them | A licence matrix of free asset sources (Kenney, Poly Haven, Quaternius CC0; Sketchfab per model; OpenGameArt per asset; Spine per user). gltf-transform recipes: 3.77 MB → 547 KB and 112 → 28 MB GPU for a hero model; meshopt by default (7 vs 59 KB decoder); re-encoding an already compressed file made it larger; spec/gloss renders untextured in three.js. Sprite strips animated with `transform: steps()` paint nothing; `background-position` repaints every frame. | `scripts/model.mjs` (glTF budget report matching three.js r186 on 116 files) |
| S4 `capability-catalogue` | Which mature library to use before building hard UI | A lookup for about 25 needs (palettes, sortable, trees, splitters, docking, node editors, rich text, crop, upload, virtualisation, grids, calendars, Gantt, gestures, CRDTs) with measured size, licence class and tested keyboard support. cmdk drops focus to `body`; dnd-kit's default announcements read ids; dockview's cross-group keyboard navigation is paid; a Bryntum npm package is a placeholder. | `libcheck.mjs` (licence class, activity, size; 34 regression cases, 15/16 correct on held-out packages) |
| S5 `configurators-editors` | Configurators, consumer editors and undo | Model first, tested exhaustively: the first rule set silently changed a customer's stated need in 237 of 13,669 transitions. Constraints: prevent, explain, warn, repair — never silently. Undo by product size: spread snapshots cost 7.1 ms p95 per move at thousands of objects; diffs 3–6 µs. Free text never in URLs or analytics. | A cake configurator prototype; a history benchmark over four strategies |
| S6 `interactive-experiences` | When interaction beats a page; game UI for the web; ambition | axe reported 0 violations on every build of a canvas toy, including the one nobody can operate by keyboard. Real buttons over the canvas completed every task for +3.3 KB; PixiJS's accessibility layer failed five ways. None of nine celebrated open-source web games uses ARIA, live regions or reduced motion. Conversion claims for 3D and AR are vendor-reported or self-selected. Ambition is set per moment, with fidelity as a separate axis. | A six-build accessible-canvas toy; a 40-minute scripted playthrough of A Dark Room; sound and haptics support from browser-compat-data |
| S7 `visual-iteration-tools` | Screenshot iteration across widths and real content; visual regression | No pixel threshold separated a 1 px shift (1,530 px) from rendering noise (4,045–11,792 px): stabilise and diff at threshold 0 instead. Playwright's default 0.2 missed a ΔE 7 brand-colour change; BackstopJS's 0.1 % missed a removed badge. A model finds 31–41 % of single-property changes by eye, so reviewers get diff regions, not "what changed?". | `scripts/sweep.mjs` (every width 320–1920 plus zoom), `scripts/stress.mjs` (pseudo-localisation, long tokens, numbers, RTL, 0/1/500 items, slow, errors) |
| S8 `rtl-mobile-haptics` | RTL at component level, Arabic metrics, mobile, haptics | `audit.mjs` caught 0 of 24 seeded RTL defects, and `widgets.mjs` tested tab arrow keys backwards for RTL. Checkmarks never mirror (every source agrees). Phone numbers, card numbers and time ranges reverse inside RTL text. `dir="auto"` on an empty field resolves to LTR in Chromium. Per-face line-height floors against harakat clipping. Haptics reach Chromium Android only. | An RTL checker, a glyph-extent probe, a mobile checker, icon-name lists from six design systems |
| S9 `polish-and-composition` | Which refinements are perceptible | Of 20 polish moves, macro space and one accent were seen and preferred; alpha borders, radius nesting and layered tinted shadows were not perceptible at the tested sizes. pixelmatch reports 0 % for hairline, shadow and tint changes (ΔE is needed). A polish pass, macro to micro, with a qualitative stop rule. | A 20-toggle page, blind pair sheets with a hidden key, a polish probe |
| S10 `shaders-generative` | Shader and generative visuals: capability, cost, value | Animated SVG filters and `@property` gradients kept the main thread 78–89 % busy (17 fps at 4×). A raw WebGL shader plus wrapper is 4.4 KB. The poster is the LCP unless it covers the whole viewport. A generative background passes only when driven by real data or a documented material, after a still and a loop were rejected. Shadertoy code defaults to CC BY-NC-SA. | Seven hero-background variants, a governor, a production checklist |
| S11 `loading-tiers-offmain` | Loading, device tiers, off-main-thread work | A heavy module behind a poster, warmed on approach, made people wait 0.18–0.24 s instead of 7.5–13.8 s on slow 4G. A worker that posts an object graph back was slower than doing the work on the main thread (741 vs 371 ms); send columns first. A tier detection order and a governor with an explicit `pause()`. | `tier.js`, `governor.js`, loading and parsing labs |
| S12 `systems-and-references` | White-label, POS, token enforcement, reference boards, after launch | Choosing a tenant fill's label by WCAG first raised all-gate passes from 3/24 to 9/24. Tailwind v4 `@theme` resolves at `:root` and silently breaks subtree tenants (`@theme inline` does not). Lint enforcement ships as warnings with a baseline (5 flags on 52k held-out lines). A live region or ticker hides dead clicks from frustration analytics. | A tenant-contrast lab, lint fixtures, a RUM snippet |

Each stream's report is `streams/<id>-<slug>.md`; its skeptical review is `streams/<id>-<slug>.review.json`; its experiment, with one runner, is `experiments/<id>-<slug>/` (`node_modules` and builds are not committed; `npm install` then the runner).

## Limits of this evidence

- No GPU: WebGL ran on SwiftShader, so GPU-bound numbers are comparable only among themselves; conclusions that would change on a real GPU are stated in each report.
- Only Chromium; iOS Safari behaviour (visual viewport, keyboard, safe areas, haptics) comes from browser-compat-data and search snippets.
- No real assistive technology; accessibility was judged from Chromium's accessibility tree and live-region logs.
- A shared, busy machine: timings are medians of at least five runs and relative.
- Most live websites were unreachable; products were studied through their open-source code and design systems.
