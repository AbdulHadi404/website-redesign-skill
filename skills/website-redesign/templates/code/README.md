# Code templates

`tier.js` picks the starting quality tier of a rich experience (a WebGL scene, a generative background, a heavy canvas) in the detection order of `interactive.md` §7: URL overrides, the display refresh measured while only the poster is on screen, the WebGL and software-renderer checks, a start guess that only lowers, and a probe of the top tier's own per-frame JS. Its `measureRefresh()` is also the budget the governor judges frames against. Tiers change resolution, effects and tessellation, never the look ([interactive.md §7](../../references/interactive.md)).

`governor.js` is the one runtime governor for any render loop. Call `frame(now)` on every rendered frame and `pause()` whenever the loop stops. It steps quality down on slow windows (`onChange`), calls `onFloor` once when even the lowest level runs below ~27 fps (show the poster), and steps back up no sooner than 30 s after a step-down, or never with `stepUp: false`. Scenes use it as `interactive.md` §7 describes; `hero-effect.js` uses it with `stepUp: false`.

`hero-effect.js` makes a generative hero background (a shader, particles, a canvas field) production-ready: poster first, a crossfade on a WebGL2 fence, no frames off-screen, hidden or paused, a pixel-ratio cap, governor.js halving the render scale, context-loss recovery, an optional settle, a Pause/Play button, and never imported under reduced motion. Whether a moving background is warranted at all is the purpose gate in `interactive.md` §9: most are decoration. Each file's header says what was tested and which numbers are heuristics [K]; copy the files with their headers, and credit borrowed effect code in `CREDITS.md`.
